# История разработки веб-приложения (Summary)
**Дата:** 15 марта 2026 г.

Этот документ содержит краткое изложение диалога и хода разработки веб-приложения для текстологического анализа и сравнения текстов (на основе `TECH_SPEC.md`).

## 1. Инициализация и Базовая настройка
- **Стек:** Python (FastAPI, SQLAlchemy, Alembic) + Node.js (Next.js, Tailwind CSS) + PostgreSQL.
- **Настройка окружения:** 
  - Решены проблемы с путями импорта в Python (`sys.path.append` в `env.py` и `main.py`).
  - Настроена аутентификация (JWT).
  - **Важное исправление:** Заменили алгоритм хеширования паролей с `bcrypt` на `pbkdf2_sha256` из-за ограничения `bcrypt` на длину пароля (72 байта), вызывавшего ошибки.

## 2. Реализация Алгоритмов (Модуль `algo`)
- **Токенизация:** Реализована базовая токенизация по пробельным символам.
- **Алгоритмы сравнения:**
  1. **Myers (difflib):** Базовый алгоритм для глобального выравнивания.
  2. **Levenshtein:** Реализован с поддержкой настраиваемых весов (Insert, Delete, Replace).
  3. **Levenshtein Nested:** Разработан гибридный алгоритм, где стоимость замены зависит от посимвольной близость заменяемых слов (нормированное расстояние Левенштейна).
- **Матрица расстояний:** Реализован расчет матрицы расстояний между множеством текстов.

## 3. База данных и Миграции
- Настроена схема БД (User, TextModel, Comparison, WordOp, CharOp, ClassCatalog, Preset и др.).
- **Каскадное удаление:**
  - Реализована функция "Clean Unused" для очистки несохраненных сравнений.
  - Для корректной работы создана миграция Alembic, добавляющая `ON DELETE CASCADE` к внешним ключам таблиц операций (`comparison_word_ops`, `comparison_char_ops`). Это позволило удалять сравнения без ручной чистки связанных таблиц.
- Добавлена поддержка новых алгоритмов в ENUM типы БД.

## 4. Фронтенд и UI/UX
- **Стилизация:** Настроен Tailwind CSS. Реализован минималистичный дизайн.
- **Визуализация сравнения:**
  - Разработан компонент отображения текста с "бейджами" для операций (Replace, Insert, Delete).
  - Исправлены проблемы верстки: наложение бейджей друг на друга, корректный перенос строк (параграфы).
  - Реализована интерактивная классификация замен через сайдбар.
- **Функциональность:**
  - Загрузка текстов и шрифтов.
  - Сохранение сравнений в историю и в пресеты.
  - Страницы статистики и матрицы расстояний.

## 5. Оценка качества (QA Pipeline)
Последний этап работы был посвящен созданию инструментов для проверки качества алгоритмов на реальных данных.

- **Данные:** 
  - `Глава 43_091test.docx` (Критический аппарат, эталон).
  - `Глава 43_t.docx` (Сырые тексты рукописей).
- **Скрипты:**
  - `testing/quality/parse_apparatus.py`: Парсит эталон, извлекает базовый текст (M10) и "истинные" операции (True Values) для заданного сигла.
  - `testing/quality/split_manuscripts.py`: Парсит файл с перемешанными строками рукописей и собирает их в отдельные чистые файлы `.docx`.
  - `testing/quality/get_algo_diff.py`: Генерирует алгоритмические сравнения.
- **Методика оценки (Matching):**
  - Разработан алгоритм сопоставления эталонных и вычисленных операций.
  - Используется `pandas` и группировка с `cumcount` (порядковый номер вхождения слова), чтобы корректно соединять (Join) повторяющиеся слова в тексте и избегать дубликатов.
- **Документация:**
  - Создана папка `docs/report1` с подробным описанием форматов файлов, алгоритма матчинга и итоговым отчетом в LaTeX.

## Текущий статус
Приложение функционально, основные модули реализованы. Ведется работа над тестированием качества алгоритмов сравнения на исторических данных.
