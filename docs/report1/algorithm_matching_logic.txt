АЛГОРИТМ СОПОСТАВЛЕНИЯ: MATCHING CANONICAL AND ALGORITHMIC DIFFS

НАЗНАЧЕНИЕ:
Корректно сопоставить два списка операций (WordOps), описывающих изменения одного и того же базового текста (M10):
1. Canonical Diffs (True Values): Список операций, полученный парсингом критического аппарата (экспертная оценка).
2. Algorithmic Diffs (Test Values): Список операций, полученный результатом работы diff-алгоритма (например, Myers или Levenshtein).

ПРОБЛЕМА:
Простое соединение (Join) по слову (`base_token`) невозможно из-за наличия повторяющихся слов в тексте.
Пример:
Текст M10: "и увидел и сказал"
True: [equal("и"), replace("увидел"), equal("и"), equal("сказал")]
Test: [equal("и"), equal("увидел"), equal("и"), replace("сказал")]

Если джойнить просто по слову "и", первое "и" из True соединится со всеми "и" из Test, создавая дубликаты и ложные связи (Cartesian product).

РЕШЕНИЕ: ИСПОЛЬЗОВАНИЕ ПОРЯДКОВОГО НОМЕРА ВХОЖДЕНИЯ (OCCURRENCE INDEX)

ШАГИ АЛГОРИТМА:

1. ПРЕОБРАЗОВАНИЕ В ТАБЛИЦЫ (DataFrames):
   Преобразуем оба списка операций (`true_values` и `test_values`) в структуры данных таблицы (DataFrame), где каждая строка соответствует одной операции над одним токеном базового текста.

2. ВЫЧИСЛЕНИЕ ПОРЯДКОВОГО НОМЕРА (Occurrence Counting):
   Для каждого списка отдельно:
   Группируем записи по самому слову (`base_token`).
   Внутри каждой группы нумеруем вхождения слова по порядку (0, 1, 2...).
   Создаем временный столбец `occurrence`.

   Пример для M10 "и увидел и сказал":
   True:
     "и" -> occurrence=0
     "увидел" -> occurrence=0
     "и" -> occurrence=1
     "сказал" -> occurrence=0

   Test:
     "и" -> occurrence=0
     "увидел" -> occurrence=0
     "и" -> occurrence=1
     "сказал" -> occurrence=0

3. ОБЪЕДИНЕНИЕ (Merging / Joining):
   Выполняем операцию объединения (`Left Join`) таблицы True с таблицей Test.
   Ключ объединения (Composite Key):
     - `base_token` (Само слово)
     - `occurrence` (Его порядковый номер)

   Логика: "Соедини первое вхождение слова 'и' из эталона с первым вхождением слова 'и' из теста".

4. РЕЗУЛЬТАТ:
   Получаем единую таблицу, где каждая строка представляет уникальный токен из базового текста M10 в его конкретной позиции.
   Столбцы результата:
     - `base_token`: Слово.
     - `op_type_true`: Операция по мнению эксперта (эталон).
     - `other_token_true`: Вариант чтения по мнению эксперта.
     - `op_type_test`: Операция, определенная алгоритмом.
     - `other_token_test`: Вариант чтения, определенный алгоритмом.

5. АНАЛИЗ (Validation):
   Сравниваем `op_type_true` и `op_type_test`.
   - Если совпадают (True Positive / True Negative) -> Алгоритм сработал верно.
   - Если отличаются -> Ошибка алгоритма (False Positive / False Negative).

   Пример анализа:
   Если `op_type_true`="replace" (замена), а `op_type_test`="equal" (совпадение) -> Алгоритм пропустил изменение (False Negative).
   Если `op_type_true`="equal", а `op_type_test`="replace" -> Алгоритм нашел изменение там, где его нет (False Positive).

ПРЕИМУЩЕСТВА:
- Устойчивость к дубликатам: Гарантирует, что каждое слово сопоставляется ровно один раз.
- Сохранение контекста: Позиция слова учитывается неявно через порядок следования одинаковых токенов.
