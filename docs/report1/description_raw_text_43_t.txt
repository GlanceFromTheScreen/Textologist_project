ОПИСАНИЕ ДОКУМЕНТА: Глава 43_t.docx
ТИП: Сырые тексты списков (Raw Data)

НАЗНАЧЕНИЕ:
Этот документ служит источником "сырых" текстов конкретных рукописей, которые будут подаваться на вход тестируемым алгоритмам сравнения. Он представляет собой набор фрагментов текстов разных рукописей, но в перемешанном порядке по строкам.

СТРУКТУРА:
Документ состоит из последовательности строк, каждая из которых содержит фрагмент текста определенной рукописи.

ФОРМАТ СТРОК:
Документ содержит два основных типа строк:
1. Заголовок стиха (Разделитель):
   - Формат: `<Номер стиха>.`
   - Пример: `43.1.`
   - Значение: Маркирует начало новой группы вариантов для конкретного стиха. Не содержит самого текста рукописи.

2. Строка с текстом рукописи:
   - Формат: `<Сигл>: <Текст>`
   - Пример: `M10: възвеселе высоты...`
   - Пример: `P81: възвеселїе...`
   - Пример: `TB: възнеⷭнїе...`
   - Сигл (M10, P81, TB, MN и т.д.): Идентификатор рукописи.
   - Двоеточие (`:`): Разделитель между Боглом и текстом.
   - Текст: Собственно текст рукописи для данного стиха.

3. Комбинированный формат (реже, но поддерживается):
   - Формат: `<Номер стиха>. <Сигл>: <Текст>`
   - Пример: `43.1. M10: текст`
   - Значение: Номер стиха и текст могут быть на одной строке.

НЮАНСЫ И ОСОБЕННОСТИ ОБРАБОТКИ:
1. Перемешанность (Interleaving):
   Тексты разных рукописей идут вперемешку. Например, сначала идет фрагмент M10, затем P81, затем TB, затем снова M10 (для следующего стиха).
   Для получения полного связного текста одной рукописи (например, P81) необходимо пройти по всему файлу, отфильтровать строки, начинающиеся с `P81:`, и склеить их содержимое в правильном порядке.

2. Отсутствие данных (Gaps):
   В отличие от критического аппарата (где "молчание" означает совпадение с M10), здесь каждая рукопись представлена явно. Если фрагмент рукописи P81 отсутствует в блоке `43.X`, это может означать физическое отсутствие текста (лакуну) или ошибку в данных. Алгоритм склейки предполагает, что все нужные фрагменты присутствуют.

3. Различия в написании:
   Текст в этом файле ("как есть") может содержать незначительные отличия от леммы в критическом аппарате (например, разную пунктуацию или spacing), что является нормальным для задачи сравнения diff-алгоритмом. Задача алгоритма — найти эти отличия.

ПРОГРАММНАЯ ОБРАБОТКА:
Файл обрабатывается скриптом `testing/quality/split_manuscripts.py`.
Скрипт выполняет следующие действия:
   - Парсит строки по регулярному выражению `^\s*([A-Za-z0-9а-яА-Я]+)\s*:\s*(.*)`.
   - Собирает все найденные фрагменты текста для каждого уникального сигла в отдельные списки.
   - Сохраняет результат в виде отдельных файлов `.docx` (например, `data/clean/P81.docx`), которые содержат полный восстановленный текст конкретной рукописи.
Эти восстановленные файлы затем используются как входные данные для алгоритма сравнения (`compare_tokens`).
